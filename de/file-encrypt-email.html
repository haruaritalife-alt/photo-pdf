Eine wichtige Datei vor dem E-Mail-Versand verschlüsseln

Veröffentlicht: 19.10.2026 | Aktualisiert: 19.10.2026 | Über uns (Japanisch)

Wichtige Punkte
  • Die Datei verschlüsseln
  • An die E-Mail anhängen
  • Das Passwort auf anderem Weg weitergeben

Emailing contracts or documents containing personal information is worrying. Email may be viewed along the way. If you encrypt with Encrypt and Decrypt a File with a Password before sending, the contents are protected even in the worst case.

Schritte

  1. With "Choose one file to encrypt or decrypt", choose the file to send.
  2. Choose "Encrypt" and enter the password twice.
  3. Press "Encrypt and save" to save.
  4. Attach the encrypted file (.pmk) to an email and send it.
  5. Tell the password by a means other than email.
Writing the password in the same email defeats the purpose of encryption. Tell it by phone or another contact method.

Preparing the recipient

Files encrypted with this tool can't be opened with other software. The recipient decrypts with this tool as well. It's considerate to tell them in advance:

  • That they decrypt with this tool
  • That the file's extension is .pmk
  • That the password will be told by another means

How to convey the password

  • Tell by phone
  • Send via another messaging app
  • Tell in person
  • Decide in advance

Cautions

  • Even encrypted, the existence of the file is visible to the recipient and third parties
  • Don't put confidential information in the file name
  • Confirm the recipient can use this tool

Gut geeignet für

  • Sending quotes, contracts, personal information
  • Sending data outside the company
  • Leaving a file for yourself

Beispiel

Needed to send an employee list to an outside person in charge. Encrypted the list and attached it to an email. Told the password by phone.

Common stumbling blocks

  • The recipient can't open it: they don't know this tool. Explain how to use it.
  • Sent the password in the same email: safety drops. Use another means.

Frequently asked questions

What if the recipient can't use this tool?

Consider another method, for example a password-protected format they can open.
